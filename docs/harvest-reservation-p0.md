# Harvest reservation P0.3
All reservation-changing HarvestController HTTP routes acquire one PostgreSQL transaction advisory lock before reading state. This serializes the check/save window, including global voucher code generation, across API processes. The shared recorder checks active assignments as well as active vouchers and history, excluding the current assignment during result submission/completion. A deferred line remains reserved until the assignment completes.
This does not protect direct database writers or unrelated profile-status mutation routes; the existing Crab concurrency token still guards concurrent final crab changes. No migration required. Test two simultaneous POSTs for the same crab in different routes: one succeeds, one returns conflict; then verify there is only one open reservation, and a valid completed harvest still releases the box and generates one history entry.
