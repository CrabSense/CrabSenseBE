# P0.2 Missing crab
Staff only: POST /api/crabs/{id}/missing {boxId,reason}. Explicit confirmation at current box, nonempty reason. Uses existing harvest advisory lock and concurrency tokens; reject active voucher or assignment, stale box, inconsistent allocations and terminal status. Status Missing (not Dead), condition Problem, actor/time/reason, close allocation, update box history, preserve crab and lot. No migration. Missing remains a distinct status in survival reports. Recovery/reinstatement is not exposed, pending a separately authorized correction workflow. Acceptance: verify allowed Staff/assigned area, other roles denied, duplicate/stale requests, concurrent harvest, history/last known box, counts, no mortality row, box available.
