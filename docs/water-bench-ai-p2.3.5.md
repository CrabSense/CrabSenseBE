# P2.3.5 — durable bounded AI retries
Additive WaterBenchAiAttempts table: maximum three attempts per session, persisted before inference, same original request ID/body, 120-second lease, 5/15-second backoff for temporary failure. HTTP 503 maps to temporary failure, AI 422 maps to retest recommendation, invalid response/configuration/contract blocks automatic retry. GET .../results/retry-status returns per-channel state. Successful persistence and attempt success share a transaction; unique assessment prevents duplicates. A stale lease cannot commit. Explicit needs_retest uses the existing FarmManage endpoint; active lease blocks retest. On BE restart resubmit exact original request after lease expiry; no autonomous background worker or automatic hardware replay. Retry is request-driven, not a scheduled automatic re-analysis. Farm Staff Mobile/Farm Manager Desktop read scoped status, Farm Admin Web manages assessment, System Admin Web technical service only; no UI changes yet. Tests cover classification, lease expiry, fencing, backoff and cap; PostgreSQL/runtime restart acceptance remains P2.3.6.
