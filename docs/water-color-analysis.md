# Water color analysis (NO2 / NO3 / ammonia)
Manual calibrated optical estimate, separate from crab YOLO and real-time sensors. No automatic pumps, reagent dosing or cleaning. Do not use to automate treatment until validated against a reference laboratory method.
- Farm Administrator: POST /api/areas/{areaId}/water-analysis/color/calibrations with cameraDeviceId, analyte (NO2, NO3 or NH3 test channel), kitName, reagentLot, protocol (width, height, sample/reference ROI, channel R/G/B, reactionSeconds, timingToleranceSeconds, sampleVolumeMl, procedure, minSalinityPpt/maxSalinityPpt), standards (3–12 including blank; each mediaId, concentration, reactionSeconds, salinityPpt), independent validation (same fields), maxValidationError, validUntil (UTC, maximum 90 days). Kit names are canonical: Sera (NO2), VASTOCEAN (NO3), Thủy Phước (NH3/NH4). For NH3/NH4, measuredUnit is required: mg/L NH3, mg/L NH4, or mg/L TAN-N, as validated by the kit/reference method. TAN/NH4 is never populated into free NH3 or compared with a free NH3 limit. Conversion needs validated method and pH, temperature, salinity. Capture every standard with identical vial/lighting/camera settings, same kit and matrix. Independent check must be inside range and error below configured limit. The software cannot verify the true standard concentration or that a human followed the chemistry protocol.
- Upload private JPEG/PNG via existing /api/media/upload with category=image, deviceId=camera ID, relatedEntityType=device, relatedEntityId=camera ID; no box/crab. Camera must have FarmingAreaId equal to the area. Fixed image dimensions; two disjoint ROIs, fixed camera exposure/white balance, stable LED and reference patch. Max 5 MB/8 MP. Images are not fetched from arbitrary URLs.
- GET /api/areas/{areaId}/water-analysis/color/calibrations (optional analyte), GET .../calibrations/{id}, POST .../calibrations/{id}/revoke.
- Farm user assigned to area: POST .../color/analyze {calibrationId, mediaId, sampleSource, sampleLocation, notes, reagentLot, reactionSeconds, salinityPpt}. Reaction time/salinity are operator-attested. No result outside calibration range or on failed quality checks. Same media ID returns same stored result (no re-analysis across profiles). Keep originals privately in media storage.
- Existing GET /api/areas/{areaId}/water-analysis and /{runId} show successful manual runs and provenance; no fake hardware ACKs or confidence. Authenticated media content is /api/media/{mediaId}/content.
- One profile per immutable calibration revision (new record for changes); revoke on reagent/camera/LED change or failed QC. No calibration is preseeded. Reference patch drift >10%, ROI variation or clipping rejection are initial engineering gates, not validated analytical limits. Need matrix-specific validation, repeatability, detection/quantitation limits and temperature/interference checks before use.
- Hardware mode remains blocked (501) until a real dispatcher and authenticated step events are integrated. Existing station no longer claims automatic AI is ready. No automatic alert emission; threshold evaluation for manual runs requires an explicitly matching ion unit (mg/L NO2 or mg/L NO3). Existing legacy trend data is not an analytical validation series. SkiaSharp with Linux native assets is used for decoding.

## Batch and schedule (planning only)
POST /api/areas/{areaId}/water-analysis/batches {targets:[{analyte:"NO2",calibrationId:"..."}],sampleSource:"RAS_RETURN"} accepts any unique selection of 1–3 configured channels.
PUT .../schedule {targets:[{analyte:"NO2",calibrationId:"..."},{analyte:"NO3",calibrationId:"..."},{analyte:"NH3",calibrationId:"..."}],sampleSource:"RAS_RETURN",intervalMinutes:720,nextRunAt:"2026-11-16T06:00:00+07:00",enabled:true}. The server uses UTC; interval 720 is an example, not a preset.
The hosted scheduler creates exactly one waiting_samples batch when due (all three), advances next due time, skips overlap and records a blocked outcome for expired calibration. It does not claim hardware execution or send commands. GET .../schedule, GET .../batches, GET .../batches/{id}, POST .../batches/{id}/cancel.
POST .../color/analyze can include batchId. Each target independently uploads its post-batch image and submits the pinned calibration. Successful results are kept even if another target has not finished. The batch becomes completed only after all requested results are stored. Cancel keeps already stored results. One active batch per area; a batch is not a hardware reservation.
Physical parallel execution needs three isolated assay channels, verified reagent order/timing/doses, mixing, waste handling, interlocks, camera capture timing, authenticated firmware ACKs and dispatcher. The kit instruction sheets and physical tests remain prerequisites. No scheduler-triggered physical start yet.
