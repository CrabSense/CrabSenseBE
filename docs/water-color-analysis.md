# Water color analysis (NO2 / NO3 / ammonia)
Manual calibrated optical estimate, separate from crab YOLO and real-time sensors. No automatic pumps, reagent dosing or cleaning. Do not use to automate treatment until validated against a reference laboratory method.
- Farm Administrator: POST /api/areas/{areaId}/water-analysis/color/calibrations with cameraDeviceId, analyte (NO2, NO3 or NH3 test channel), kitName, reagentLot, protocol (width, height, sample/reference ROI, channel R/G/B, reactionSeconds, timingToleranceSeconds, sampleVolumeMl, procedure, minSalinityPpt/maxSalinityPpt), standards (3–12 including blank; each mediaId, concentration, reactionSeconds, salinityPpt), independent validation (same fields), maxValidationError, validUntil (UTC, maximum 90 days). Kit names are canonical: Sera (NO2), VASTOCEAN (NO3), Thủy Phước (NH3/NH4). For NH3/NH4, measuredUnit is required: mg/L NH3, mg/L NH4, or mg/L TAN-N, as validated by the kit/reference method. TAN/NH4 is never populated into free NH3 or compared with a free NH3 limit. Conversion needs validated method and pH, temperature, salinity. Capture every standard with identical vial/lighting/camera settings, same kit and matrix. Independent check must be inside range and error below configured limit. The software cannot verify the true standard concentration or that a human followed the chemistry protocol.
- Upload private JPEG/PNG via existing /api/media/upload with category=image, deviceId=camera ID, relatedEntityType=device, relatedEntityId=camera ID; no box/crab. Camera must have FarmingAreaId equal to the area. Fixed image dimensions; two disjoint ROIs, fixed camera exposure/white balance, stable LED and reference patch. Max 5 MB/8 MP. Images are not fetched from arbitrary URLs.
- GET /api/areas/{areaId}/water-analysis/color/calibrations (optional analyte), GET .../calibrations/{id}, POST .../calibrations/{id}/revoke.
- Farm user assigned to area: POST .../color/analyze {calibrationId, mediaId, sampleSource, sampleLocation, notes, reagentLot, reactionSeconds, salinityPpt}. Reaction time/salinity are operator-attested. No result outside calibration range or on failed quality checks. Same media ID returns same stored result (no re-analysis across profiles). Keep originals privately in media storage.
- Existing GET /api/areas/{areaId}/water-analysis and /{runId} show successful manual runs and provenance; no fake hardware ACKs or confidence. Authenticated media content is /api/media/{mediaId}/content.
- One profile per immutable calibration revision (new record for changes); revoke on reagent/camera/LED change or failed QC. No calibration is preseeded. Reference patch drift >10%, ROI variation or clipping rejection are initial engineering gates, not validated analytical limits. Need matrix-specific validation, repeatability, detection/quantitation limits and temperature/interference checks before use.
- Hardware mode remains blocked (501) until a real dispatcher and authenticated step events are integrated. Existing station no longer claims automatic AI is ready. No automatic alert emission; threshold evaluation for manual runs requires an explicitly matching ion unit (mg/L NO2 or mg/L NO3). Existing legacy trend data is not an analytical validation series. SkiaSharp with Linux native assets is used for decoding.

## Batch and schedule (planning only)
POST /api/areas/{areaId}/water-analysis/batches {targets:[{analyte:"NO2",calibrationId:"..."}],sampleSource:"RAS_RETURN"} accepts any unique selection of 1–3 configured channels.
PUT .../schedule {targets:[{analyte:"NO2",calibrationId:"..."},{analyte:"NO3",calibrationId:"..."},{analyte:"NH3",calibrationId:"..."}],sampleSource:"RAS_RETURN",intervalMinutes:720,nextRunAt:"2026-11-16T06:00:00+07:00",enabled:true}. The server uses UTC; interval 720 is an example, not a preset.
The hosted scheduler creates exactly one waiting_samples batch when due (all three), advances next due time, skips overlap and records a blocked outcome for expired calibration. It does not claim hardware execution or send commands. GET .../schedule, GET .../batches, GET .../batches/{id}, POST .../batches/{id}/cancel.
POST .../color/analyze can include batchId. Each target independently uploads its post-batch image and submits the pinned calibration. Successful results are kept even if another target has not finished. The batch becomes completed only after all requested results are stored. Cancel keeps already stored results. One active batch per area; a batch is not a hardware reservation.
Physical parallel execution needs three isolated assay channels, verified reagent order/timing/doses, mixing, waste handling, interlocks, camera capture timing, authenticated firmware ACKs and dispatcher. The kit instruction sheets and physical tests remain prerequisites. No scheduler-triggered physical start yet.

## Versioned assay catalog and operator-assisted channel state machine
GET /api/areas/{areaId}/water-analysis/assay-profiles returns three reference recipes and versioned chart metadata. Sera 04410 2015 protocol (5 mL, 5+5 drops, 300 s) uses the original chart 0/0.5/1/2/5 mg/L; the newer comparator chart is separately listed (≤0.01/0.2/0.5/0.8/1/1.5/2/5), not substituted for the older recipe. New comparator protocol needs separate verification. VASTOCEAN NO3 third-party instructions (5 mL, 7+7 drops, one-third kit scoop, 10 s shake, 7 drops R3, 120 s) and Thuy Phuoc NH3/NH4 retailer directions (5 mL, 5+5 drops, 600 s) are reference-only until matched to actual kit. Their numeric charts remain unavailable, not invented. URLs point to source documents; no screen RGB is used as calibration. Catalog recipes are code-versioned; each WaterAssayChannel stores immutable profile/steps/chart references plus calibration protocol JSON, rather than mutable duplicate reference tables.
Each batch creates independent channels at the same server time, each pinned to calibration. Batch readiness requires protocol sample volume and reaction time match recipe and >=5 s timing tolerance. The client must explicitly attest matching the kit and instructions at the rinse step. POST .../batches/{id}/channels/{analyte}/steps {step:"rinse",action:"confirm",kitInstructionsConfirmed:true}; for later steps send the exact current step code and action "confirm". No physical commands are sent. The wait timer starts after last mix confirmation; wait and capture confirmation require server time within calibrated reading window. Capture includes private mediaId uploaded after reaction-ready time. Use separate Media IDs for each channel (including a shared camera); the server does not verify actual capture time or sample identity from an upload. Analyze via .../color/analyze with batchId and the captured Media ID. The successful result is stored immediately; channel remains cleanup_required until operator confirms cleanup. Use {step:currentStep,action:"fail",reason:"..."} for a failure, then confirm cleanup. No chemical waste returns to RAS; use a separate compatible waste collection and approved disposal. A batch completes only when every channel has reached terminal state; failed+successful is partial. Cancel only untouched channels after any started channels have been cleaned. Retry a failed assay in a new batch. All event times and actors are saved; acknowledgements are operator attestations, not hardware evidence.
Scheduled mode creates three waiting channels, NOT automatic dispensing. No pump/valve/GPIO mappings, ml-per-drop assumptions or powder mass conversion are supplied. NO3 solid dosing and mixing, chamber separation, calibrated dispense volume, safe waste routing, stop/fault interlocks and actual firmware/worker acknowledgements remain hardware prerequisites. A shared camera needs distinct per-assay view/ROI and timing; Sera legacy top-view and the other side-view assays may need separate optics.

## Independent Python water AI integration
New calibrations use CrabSenseAIWaterQualityAnalysis (https://github.com/CrabSense/CrabSenseAIWaterQualityAnalysis) /v1/calibrations/fit. Configure WaterAi__BaseUrl (private HTTPS or loopback HTTP, e.g. http://127.0.0.1:8080) and WaterAi__ApiKey (matches WATER_AI_API_KEY, >=32 chars) on BE. The Python service has a separate WATER_AI_SIGNING_KEY, persistent across restarts; never put either secret in Git. Deploy AI first, apply migration 20261116000000_WaterAiExternalCalibration, then deploy BE. New calibration requests require kitRevision (actual kit revision), and protocol.channel accepts AUTO or legacy R/G/B (Python learns channel regardless); standards and validation use existing authenticated private Media IDs. Total decoded input max 28 MiB per calibration. BE persists signed token, external ID, algorithm, curve and holdout; token is omitted from public JSON. No direct client access to AI. Existing local curves remain local, no automatic conversion. Recalibrate to migrate; no remote failure fallback. BE validates response scope, unit, algorithm, media ID and SHA-256 before saving. Result source water-ai-python; no artificial confidence. Existing batch step confirmation and cleanup rules remain. Each ready channel can call color/analyze independently, concurrently; BE serializes only the short save transaction per batch. No new BE bulk endpoint: the Python batch endpoint exists but BE currently uses one call per channel, preserving individual retries and existing authorization. AI outages return 503 without saving fabricated results. Physical tests and calibration still required.
## Quality-control integration
New Python calibration has QualityCheckDueAt (default 168h, configurable WaterAi__QualityCheckIntervalHours 1–720; cannot exceed expiry). Migration backfills existing Python profiles at min(expiry,created+7d); legacy C# profiles unchanged. POST .../color/calibrations/{id}/checks (FarmManage) accepts mediaId, expected, maxError, reagentLot, reactionSeconds, salinityPpt; AI evaluates independent control and BE stores WaterCalibrationChecks, renews due date or revokes failed calibration. GET .../checks is area-scoped. Scheduled/manual batch planning and final result save reject overdue/revoked calibrations. A failed optical image is rejected without a chemical QC result; repeat with valid control. GET checks history, audit, and review actual control reference concentrations. POST .../color/inspect accepts calibrationId, mediaId, reactionSeconds, salinityPpt, calls Python ROI inspection without recording a measurement. Geometry checks not yet pinned to station hardware. New result hashes unique per area; prevents exact reupload across new analysis runs; old results not backfilled, edited images not guaranteed detected. Control hashes unique per profile. New endpoints require upgraded Python PR #2 service before deployment. Ammonia conversion remains explicit research/preview until kit measurand and sensor-source/time matching validated; no automatic NH3 toxicity alerts.
## Geometry-gated water AI v2
Deploy Python PR #3 first. New BE calibration requests default to requiring protocol.geometryPolicy={anchor:{x,y,width,height},maxShift:4,minCorrelation:0.92,minFocusRatio:0.5}; physical textured holder marker 16–64 px, disjoint from sample/reference ROIs and search margins. WaterAi__RequireGeometryForNewCalibration=false explicitly allows legacy new fits during migration; existing v1 and C# profiles retain behavior. Set WATER_AI_REQUIRE_GEOMETRY=1 on the Python service after clients supply the geometry policy. BE persists the chosen version in existing AiAlgorithm, policy in ProtocolJson, and signed template in private token. No new schema migration required for v2. BE verifies version and aligned geometry evidence in inference/control and routes inspect to the signed profile; results include real algorithm in history. Version rollback is explicit profile selection/recalibration, not fallback on rejection. No certified vial presence, fill level or bubbles: research CNN is not served. No new physical command dispatcher or client UI. Offline dataset curation and model research registry live in the AI repository; production model approval/deployment requires exact-kit validation and future BE workflow.

### Reviewed concentration dataset
FarmManage endpoints under /color/calibrations/{id}: POST training-samples (mediaId, preparationId, split, labelSource, referenceId, concentration, reactionSeconds, salinityPpt), GET training-samples (paginated), POST training-samples/{sampleId}/withdraw, GET training-manifest. Only independent certified_standard/reference_lab labels, reviewer and hash are stored. No automatic AI prediction labels. Registration checks signed V2 optics and locks calibration to prevent preparation split leakage; same area image hash unique. Withdrawal is audited and omitted from export; original records retained. Export returns domain + sample metadata; download each authorized private media to images/{mediaId}.img beside reviewed.json, then run Python dataset CLI and training CLI. The export is a point-in-time metadata response, not a zip or automatic training job; operator must preserve files and manifest. Migration adds WaterTrainingSamples. No cross-kit pooling; research approval/deployment not automated.
